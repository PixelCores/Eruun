# Context Packet (可选任务简报)

当任务涉及多个契约、风险较高或需求存在歧义时，用这份简报快速锁定边界。普通任务不需要填表，Agent 应从仓库中自行获取可发现上下文。已有任务计划或状态记录时复用其中的信息，无需另建一份简报。

---

## 快速模板

```markdown
### Goal (目标)
一句话描述期望效果

### Scope (范围)
- 文件: `path/to/file.go`
- 符号: `func Foo()`, `type Bar`

### Current → Expected (现状与期望)
- 现状:
- 期望:
- 错误日志（如有）:

### Constraints (约束，可选)
- 兼容性:
- 性能要求:

### Deliverables (期望输出)
- [ ] 代码
- [ ] 测试
- [ ] 文档
- [ ] Devlog
- [ ] PR 文案
```

---

## 填写示例

以下是虚构的边界校验示例，只演示简报写法，不描述 Eruun 的当前路径或 API 契约。实际任务应填入已核实的文件和符号。

```markdown
### Goal
修复请求校验接受非法负数上限的问题

### Scope
- 文件: `<已定位的校验文件>`
- 符号: `<已定位的校验函数>`

### Current → Expected
- 现状: 复现用例中负数上限被接受
- 期望: 按已确认的契约拒绝负数；保留零值和正数的原有行为
- 错误日志: 无

### Constraints
- 必须兼容现有 API 响应格式

### Deliverables
- [x] 代码
- [x] 测试
- [ ] 文档
- [ ] Devlog（仅在存在持久且非显然的技术决策时需要）
```

---

## 最小信息集

如果需要主动补充上下文，优先提供：

1. **Goal** - 一句话目标
2. **Current → Expected** - 复现步骤、错误输出或验收结果
3. **Constraints** - 仓库中无法推断的契约或取舍

---

## 提供代码片段的原则

| ✅ 做 | ❌ 避免 |
|------|--------|
| 仅贴关键片段 (30-120行) | 整文件粘贴 |
| 标注路径和符号名 | 无上下文的代码块 |
| 包含调用方/被调用方 | 仅贴单个函数 |
